# AKDesk Fixed v0.7.0「整合研究版」

> 适用版本：v0.7.0  
> 定位：个人免费使用、本地优先的宏观固收行情与研究工作台  
> 合并范围：原 v0.6.2、v0.6.3 与信用观察 R1

## 1. 版本目标

v0.7.0 把“看到市场变化”推进到“形成可复盘的研究记录”。用户可以从中国固收行情、自选或市场线索一键立项，持续记录笔记、反证、任务和复盘；也可以在宏观数据发布前保存自己的预期，发布后按需请求 FRED 官方实际值并检查市场窗口。

信用观察从占位页升级为 R1，但采用严格的覆盖门禁：只有主体、到期日、评级及日期、债券收益率及日期、同日国债基准、期限匹配和来源说明全部通过，系统才做机械利差试算。该模块不是评级系统，也不输出违约概率。

## 3. 研究项目工作台

### 3.1 从哪里立项

以下位置提供“一键创建研究项目”按钮：

- 市场研究线索；
- 统一自选；
- 现券市场；
- 国债期货；
- 可转债；
- 信用观察。

立项时会保留对象代码、名称、来源和观测时间等上下文。用户也可以在“研究项目”页面使用空白研究、中国利率方向、宏观数据发布、可转债事件和信用观察模板。

### 3.2 研究记录

每个项目可新增四类记录：

- 研究笔记：记录新事实、模型结果和阶段性判断；
- 反证：专门保存与当前假设冲突的信息；
- 任务：记录下一步核验事项，可设置日期和完成状态；
- 复盘：在观点形成后记录偏差、失效条件和改进。

记录的新增、状态变化和删除都会进入观点轨迹，便于回看研究过程，而不仅是最终结论。

### 3.3 导入、导出与备份

- Markdown 导出适合阅读、归档和分享不含行情值的研究结论；
- JSON 项目包适合在 AKDesk 实例间迁移单个项目；
- JSON 导入会创建带“（导入）”后缀的新项目，不覆盖原项目；
- “备份研究库”下载完整 SQLite；
- “恢复备份”先校验文件完整性和 AKDesk 表结构，再自动保存当前库的安全副本并恢复。

FRED 研究证据在项目包中仍只包含序列、区间、来源、变换和链接引用，不包含官方观测值。服务端会拒绝导入含 FRED 数值数组的项目包。

## 4. 行情增强自选与线索阈值

统一自选会尽量匹配最近缓存中的现券、期货或转债行情，并展示：

- 主要价格或收益率；
- 涨跌或 BP 变化；
- 数据来源、可信等级和观测时间；
- 前往对应行情页面的入口。

宏观自选不会在后台自动请求 FRED，而是显示“按需请求”，避免为了刷新自选而扩大 FRED 数据处理范围。

投研首页的资金、曲线、期限利差、期货和现券线索阈值可以本地调整。每条线索同时展示触发原因，阈值只用于筛选关注程度，不等于交易信号。

## 5. 每周研究复盘

“每周研究复盘”默认汇总最近七天：

- 活跃项目与本周有更新的项目；
- 研究笔记和新增反证；
- 已完成和未完成任务；
- 数据发布复盘；
- 已到复盘日期的项目。

用户可以选择周结束日并导出 Markdown。周报只汇总本地活动，不自动生成投资观点。

## 6. 数据发布复盘

### 6.1 发布前

进入“数据发布复盘”，选择 FRED 序列，填写发布日期、目标观测期、手工预期值、单位、依据和可选关联研究项目。此时本地只保存用户输入的预期。

### 6.2 发布后

点击“请求官方实际值”，系统才向 FRED 发起本次请求，并返回：

- 目标观测期的官方实际值；
- 实际值减手工预期值的偏差；
- 当前 realtime vintage；
- 与上次标记版本相比是否变化；
- 本地已有的 Shibor O/N、10Y 国债、10Y–1Y 和 T 合约前后窗口。

如果目标观测期尚未发布，实际值保持为空。市场窗口只使用本地已有的可信历史，缺失日期不会插值或伪造。

### 6.3 FRED 存储边界

FRED 官方实际值只存在于本次 HTTP 响应和当前页面状态中，不写入 SQLite。数据库仅保存：

- 用户预期；
- 发布与观测日期；
- 用户备注；
- 关联项目；
- 用户主动标记的 vintage 引用。

因此，重新进入页面后需要再次点击“请求官方实际值”。这是有意设计的数据边界。

## 7. 信用观察 R1

### 7.1 输入与覆盖率

信用观察以用户核验后的本地录入为准，字段包括债券代码、名称、发行人、到期日、债项评级及日期、到期收益率及日期、国债基准期限及收益率、基准日期和来源说明。

页面展示逐字段覆盖率和整体通过率。行情缓存可以辅助提供债券代码、名称、收益率和国债曲线候选，但不会自动补造发行人、评级或到期日。

### 7.2 计算门禁

以下任一条件不满足时显示“不计算”：

- 关键字段缺失；
- 评级不在 R1 支持的 AAA 至 BBB- 范围；
- 评级日期晚于债券收益率日期；
- 债券收益率与基准收益率不是同一观察日；
- 债券在观察日已经到期；
- 剩余期限与所选 1Y、3Y、5Y、7Y、10Y 基准不匹配；
- 缺少人工来源说明。

全部通过后，系统只计算：

```text
信用利差（BP） =（债券到期收益率 - 同日同期限国债基准收益率）× 100
```

该结果不包含流动性、税收、选择权、估值偏差或主体基本面调整，不构成内部评级、违约概率或投资建议。

## 8. 本地数据与升级

v0.7.0 将 SQLite schema 升级至 `700`，新增研究记录、发布复盘、信用观察、应用设置和迁移记录。首次启动会自动迁移，既有研究项目、自选、提醒、日报和市场历史不会被清空。

建议升级前关闭旧版本进程。启动后可在“数据健康”确认版本为 `0.7.0`，并在研究项目页执行一次“备份研究库”。

## 9. MacBook Air 运行方式

双击项目根目录的 `start-macos.command`。应用继续只监听 `127.0.0.1:8765`，前端使用预构建静态资源，日常运行不要求 Docker 或常驻 Node.js。

开发验证命令：

```bash
PYTHONPATH=backend .venv/bin/pytest backend/tests
cd frontend && npm test && npm run build
```

## 10. 已知边界

- AKShare/AKTools 与公开端点可能在非交易时段、源站限流或字段变化时降级；
- 信用观察 R1 依赖用户核验输入，不是自动信用数据库；
- FRED 实际值不离线缓存，发布复盘重新打开后需再次请求；
- World Bank、主权比较、组合持仓和多人协作不在 v0.7.0 范围；
- 本软件仅供个人学习与研究，不适合作为交易、估值入账或风控限额的唯一依据。
