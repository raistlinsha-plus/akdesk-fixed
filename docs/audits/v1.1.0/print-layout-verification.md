# v1.1.0 一页简报离线打印排版核验

核验日期：2026-10-22（Asia/Shanghai）。结论：固定示例的离线 PDF 为一页 A4 横向；增加 1000 字中文人工备注后自然扩展为两页，文字完整且未裁切。**这不是浏览器原生打印验收，macOS 打印对话框、浏览器页眉页脚及实际打印机输出仍待人工验证。**

## 方法与范围

- 使用 ReactDOMServer 渲染真实的 `OnePageBrief` 组件，输入为静态演示所用的 `DEMO_BRIEF`，未另写简化版打印模板。
- 直接嵌入实际的 `frontend/src/brief.css`，仅模拟 `printBriefElement` 设置的 `data-akdesk-brief-print`、打印目标及祖先类名；关闭非打印操作按钮。
- 用临时工具环境内的 WeasyPrint 70.0 进行离线文档渲染，随后以 Poppler 将每页 PDF 转成 PNG 逐页目检。未调用浏览器、系统打印窗口、Playwright、Chromium 或 CDP。
- 用 pdfplumber 提取文本与文字边界，检查页数、纸张大小、示例标识及长备注完整性。工具只安装在忽略目录下的临时环境，未加入产品运行依赖，也未增加 PDF 后端接口。
- 输入全部来自固定合成样例与人工生成备注，未读取个人研究数据、账户或 API Key，未请求外部行情或 AI。

临时渲染脚本使用项目现有 esbuild 将真实组件与示例数据打包为 Node 脚本，再调用 ReactDOMServer；CSS 导入由脚本读取的实际文件替代，未为渲染器修改产品 CSS。PDF 创建前已按 PDF 技能完成 artifact operation 标记。

## 限制与后续人工检查

WeasyPrint 与浏览器是不同的排版引擎。本次渲染器忽略了不支持的 650 字重、屏幕宽度媒体条件和 `text-shadow`；打印规则仍明确指定三列及 A4 横向，目检结果正常。这不能证明特定浏览器对这些属性、命名页面或分页行为完全一致。

设备解锁后仍需在支持的浏览器内执行一次真实“打印 / PDF”：确认只打印简报、默认一页横向、1000 字备注自然扩页、退出打印后页面正常恢复，并确认完整复盘与每周复盘的纸张设置不被简报的命名 `@page` 影响。浏览器自动页眉页脚、用户纸张/缩放设置以及真实数据源更长的名称与备注均可能改变页数；“一页”针对本次常规样例，不是对任意内容强制截断的保证。
