## 3. 审查中发现并修复

### 3.1 生成中只轮询一次

初版用一次性定时器读取任务状态；如果读取时仍在运行，后续不会再次轮询。已改为仅在 `queued/running` 状态存在时运行的 1.5 秒间隔轮询，任务结束自动清理。

### 3.2 上游成功但最终回答为空时不计用量

初版在解析最终回答之后才记录 token，导致上游已成功计费但本地预算未反映。已改为收到有效响应后先记录 usage，再解析可展示内容；空最终回答由页面队列安全重试一次。

### 3.3 页面指纹随请求时间持续变化

初版上下文中的 `generated_at` 会让每次状态请求得到不同指纹。已从稳定指纹输入中排除请求构造时间，同时保留真正业务字段变化。

### 3.4 失败状态按钮文案不明确

失败且无摘要时原按钮仍显示“生成洞察”。已改为“重试生成”。

### 3.5 未知运行错误可能直接显示

已把可展示错误限制为 AI provider、未配置、繁忙和预算异常；其他异常统一返回本地安全错误，不向页面泄漏技术细节。

### 3.6 无时区生成时间的每日触发判断

已兼容无时区历史时间：按上海时区解释后再判断“每日首次打开”，避免系统时区差异造成误触发。

## 5. 非阻断边界

- 当前正式信用库没有观察单券，因此正式信用实测覆盖的是“零数据”边界；有数据的结构裁剪与字段排除由自动测试覆盖。
- Python 测试仍有 1 条 Starlette `TestClient` 未来弃用提示，只影响测试适配层，不影响本地服务。
- npm 默认镜像不支持安全审计接口；改用 npm 官方 registry 后审计通过，0 个生产依赖漏洞。
- 自动触发是进入页面后的条件触发，不是后台定时摘要。
