# AKDesk Fixed v0.6 迭代规划

> 此初版已由 [v0.6 投研工作台规划 v2](./AKDesk-Fixed-v0.6-投研工作台规划-v2.md) 替代；保留本文仅用于追踪规划演进。

## 1. 版本定位

版本代号：`v0.6「自选研究工作台版」`

核心目标：把当前“加入自选后查看列表”的能力升级为个人研究工作流，并在可信数据边界内发布第一版可用的“信用观察”。用户每天打开应用后，应能回答三个问题：

1. 我的关注标的今天发生了什么变化？
2. 哪些标的需要继续研究、记录或设置提醒？
3. 信用债相对基准曲线的利差、评级和到期结构是否出现值得关注的变化？

v0.6 继续坚持本地优先、个人免费、公开数据可解释、异常数据不进入研究结论四项原则。

## 2. 目标用户与核心场景

面向以 MacBook Air 为主要设备的个人固收研究者，覆盖以下高频场景：

- 开盘前：查看自选标的最近快照、待处理研究项和数据可用状态。
- 盘中：按收益率、BP 变动、成交活跃度或信用利差快速找到异动标的。
- 收盘后：记录研究结论，回看当日变化，并把重点标的纳入提醒。
- 信用筛查：按发行人、评级、剩余期限和信用利差筛选可研究债券。
- 数据异常时：明确知道指标缺失、缓存、过期或被隔离，不把空值误当成“无变化”。

## 3. 功能范围

### 3.1 自选研究工作台

#### 工作台总览

- 自选分组：支持默认分组、自定义分组、调整分组和组内排序。
- 标签体系：支持用户自定义标签，如“重点”“待验证”“持有”“发行人跟踪”。
- 今日变化：统一展示现券、期货和可转债的最新值、日内变化、观察时间和数据状态。
- 研究状态：支持“待研究 / 跟踪中 / 已完成”状态及最近更新时间。
- 快速筛选：按标的类型、分组、标签、研究状态、数据健康和是否有提醒筛选。
- 快捷操作：直接进入标的研究页、添加笔记、创建提醒或从自选移除。

#### 标的研究页

- 基础信息卡：代码、名称、类型、期限、来源和数据可信状态。
- 行情快照：当前值、变化、最近观察时间和可用历史区间。
- 关联研究：展示已有提醒、最近触发、笔记和所属分组/标签。
- 研究笔记：本地保存纯文本笔记，支持自动记录更新时间和手动标记研究状态。
- 数据说明：字段级展示缺失、推断、缓存或异常隔离原因。

#### 每日工作流

- 首页新增“自选异动”和“待研究”入口。
- 每日复盘新增自选摘要：异动数量、重点标的、信用观察变化和待办研究项。
- 提醒中心创建规则时，可从当前工作台筛选结果直接选择标的。

### 3.2 信用观察 R1

信用观察 R1 是可解释的公开数据筛查工具，不包装成完整信用评级或违约预测系统。

#### 信用债列表

- 核心字段：债券代码、债券名称、发行人、债券类型、最新收益率、剩余期限、票面利率、主体/债项评级及评级日期。
- 相对估值：按债券剩余期限对同日基准曲线进行线性插值，计算“最新收益率－基准收益率”的参考信用利差。
- 筛选排序：发行人、评级、剩余期限、收益率、信用利差、观察日期和数据可信状态。
- 自选联动：信用债可直接加入研究工作台，并保留信用观察上下文。

#### 发行人观察

- 聚合发行人存量债券数量、评级分布、最近到期债券和可用利差区间。
- 展示同一发行人债券的期限—收益率/利差散点，帮助识别相对异常标的。
- 主体映射不确定时显示“待确认”，不得自动合并到发行人结论。

#### 信用数据可信边界

- 每个评级必须保留评级类型、评级值、发布日期和来源；无日期评级不作为最新评级结论。
- 信用利差必须展示基准曲线、曲线日期、插值期限和债券行情日期；日期不一致时标记为“参考值”。
- 缺少可信代码、剩余期限或基准曲线的记录不计算信用利差。
- 异常收益率、过期行情和主体映射冲突的记录保持可见但进入隔离状态，不参与排名、提醒和日报摘要。
- 页面展示数据覆盖率，禁止用 `0` 代替未知值。

## 4. 数据与技术设计

### 4.1 数据源准入门槛

正式开发信用页面前先完成数据 POC。候选 AKShare / AKTools 接口需满足：

- 目标信用债样本的可信代码覆盖率不低于 95%；
- 发行人可确定映射覆盖率不低于 90%；
- 评级和行情均有可解释的观察日期；
- 单次抓取可在现有隔离进程超时和两路并发约束内完成；
- 接口失败时存在可用的持久缓存降级路径。

未达到门槛的字段保留为实验数据，不进入 v0.6 正式指标。

### 4.2 本地数据模型

在现有 SQLite 基础上做向后兼容迁移，建议新增：

- `watchlist_groups`：分组名称、顺序和创建时间；
- `watchlist_item_meta`：分组、研究状态、排序和最近研究时间；
- `watchlist_tags` / `watchlist_item_tags`：本地标签及关联；
- `research_notes`：标的类型、标的代码、正文和更新时间；
- `issuer_entities`：规范发行人、来源标识和映射可信状态；
- `credit_snapshots`：债券、发行人、评级、剩余期限、参考利差及完整数据日期。

所有迁移必须保留现有自选、提醒、触发历史和日报归档。

### 4.3 服务约束

- 继续使用有界刷新队列，信用源不得突破最多两路外部数据进程。
- 自选工作台优先读取本地快照，页面首屏不等待信用扩展源完成。
- 信用快照按观察日期幂等写入，默认滚动保留 400 天。
- 新接口返回统一 `SourceMeta`，并复用 `trusted / partial / suspicious / unavailable` 可信等级。

## 5. 交互与信息架构

导航调整建议：

```text
工作台
├── 固收首页
├── 自选研究
└── 提醒中心（顶部入口）

市场
├── 资金面
├── 收益率曲线
├── 现券市场
├── 国债期货
├── 信用观察
└── 可转债

研究
├── 每日复盘
├── 国债发行
├── 固收计算器
└── 数据健康
```

自选研究首屏使用“摘要卡＋筛选条＋紧凑表格”结构，适配 1440×900 的 MacBook Air 视口。标的详情采用独立页面，避免把大量研究信息塞入侧边抽屉。

## 6. 版本拆分

### v0.6.0 — 自选研究工作台 MVP

- 自选分组、标签、研究状态和排序；
- 标的研究页与本地笔记；
- 自选行情快照、数据状态、筛选和快捷提醒；
- 首页与每日复盘的自选摘要；
- 信用数据 POC、发行人规范化与覆盖率报告；
- 数据库无损迁移和工作台 API 测试。

### 后续独立版本 — 信用观察 R1

> 说明：本节是早期范围草案。实际 v0.6.1 已调整为“市场投研联动版”，信用观察 R1 不再与该小版本绑定。

- 信用债列表、发行人观察和参考信用利差；
- 评级日期、曲线日期、行情日期和覆盖率可视化；
- 信用标的一键进入自选研究工作台；
- 信用利差异动进入每日复盘和提醒试算；
- 异常隔离、历史快照和信用数据源健康监控。

## 7. 验收标准

### 产品验收

- 用户可在 3 次操作内完成“把标的加入分组—记录笔记—创建提醒”。
- 自选列表刷新后分组、标签、研究状态和笔记不丢失。
- 同一标的在首页、市场页、研究工作台和提醒中心的自选状态一致。
- 信用列表所有计算值均可追溯到债券行情日期和基准曲线日期。
- 数据未知、异常、缓存和过期四种状态在界面上可区分。

### 性能验收

- 有缓存时，MacBook Air 本地工作台 API 的 P95 响应时间低于 300 ms。
- 工作台首屏不因信用扩展源阻塞，静态资源生产构建保持可用。
- 外部抓取仍最多两路并发，刷新队列有界且相同数据源请求去重。

### 质量验收

- 后端覆盖数据库迁移、发行人映射、曲线插值、日期错配、异常隔离和缓存降级测试。
- 前端覆盖分组/标签状态、筛选分页、笔记保存失败、信用空值和异常标的保护测试。
- 键盘可完成工作台筛选、标的进入、笔记保存和提醒创建；弹层焦点可正确约束和归还。
- 全量回归、生产构建、macOS 启动脚本检查和隔离端口 API 冒烟全部通过。

## 8. 明确不做

v0.6 不包含云同步、多人协作、组合持仓盈亏、自动交易、专业估值入账、付费实时行情、完整舆情抓取、AI 自动评级或违约概率预测。上述能力会显著改变数据授权、风险责任或系统复杂度，应在后续版本单独评估。

## 9. 建议实施顺序

1. 先做信用数据 POC 和覆盖率报告，以数据可用性决定 R1 字段边界。
2. 完成自选数据模型迁移、分组/标签/笔记 API 和无损迁移测试。
3. 交付自选研究工作台及标的研究页，接入首页、复盘和提醒。
4. 在已验证字段上实现信用债列表、发行人观察和参考利差。
5. 完成异常隔离、性能、可访问性和 MacBook Air 回归后发布。
