## 4. 评审中发现并修复的问题

### P1：专题证据可能跨研究对象串线

同一研究项目关联多个专题时，原实现只按项目筛选证据，可能让人民币专题证据出现在中国利率专题中。

修复后，专题时间线同时校验项目关联和 `research_evidence_objects` 对象关联；新增跨对象隔离回归测试。

### P1：项目包导入未完整恢复证据对象关联

原导入顺序先写证据、后写研究对象，导致导入证据没有恢复对象映射；非法对象类型也可能在项目创建后才失败。

修复后，导入前先完整校验对象类型，先恢复对象和项目映射，再导入证据；非法对象包不会留下半成品项目。

### P1：跨专题证据篮提交只保留一个对象

来自专题 A 的证据在专题 B 中提交时，原实现会在“来源对象”和“当前对象”之间二选一。

修复后同时保留来源对象与目标专题对象，并同步项目对象关系。

### P2：专题深链会把用户选择强制跳回

从搜索进入带专题 ID 的深链后，用户点击其他专题可能被 effect 再次重置到初始专题。

修复后只在深链参数实际变化时应用初始选择。

### P2：删除专题和证据篮可能遗留无引用研究对象

增加安全清理：只有对象不再被专题、项目、证据或证据篮引用时才删除，不影响仍在使用的对象。

### P2：证据篮存在嵌套交互控件

原结构把删除按钮放在复选框 `label` 内，键盘和辅助技术语义不理想，也可能误触选择。

修复后复选框标签和删除按钮成为同级控件。

### P2：旧版 Safari 兼容性

移除专题布局对 CSS `:has()` 的依赖，并替换 Safari 15.4 之前不可用的 `Array.prototype.at` 和 `Object.hasOwn`。

## 5. 数据源现状

运行态共有 14 个数据源，0 个被阻断。评审时处于中国市场盘前，多数日频或盘前来源显示“受限可用”是状态与研究门禁的正常表达，不代表接口全部不可用。

可信且正常：

- FRED：真实请求后 `trusted / ready`；
- World Bank：`trusted`；
- Shibor、FR、FDR、LPR、人民币参考价、发行事件：质量分 100；
- 中国收益率曲线：质量分 96，仅最新曲线缺少 1 个期限点；
- 国债期货：盘前缓存可用，质量分 95；
- 全球外币对：可展示即时询价，但来源不提供可信市场时间，因此保持部分可用。

仍需后续改善：

- 现券公开源 250 条记录均缺少可验证债券代码，质量分 45；当前系统已隔离其研究写入和自动提醒能力。
- 可转债当前备用源只有价格字段，缺少完整的溢价率、YTM 和可信市场时间，质量分 60。

这两项是公开数据源质量问题，不是 v0.9 专题模型错误，但会限制市场模块的完整体验。

## 7. 仍保留的风险与非阻断项

### 7.1 专题数量扩大后的请求放大

专题列表当前逐项读取详情；专题详情会按关联项目分别请求摘要。个人使用的少量专题没有性能问题，但当专题超过约 50 个或单专题关联大量项目时，会出现 N+1 请求和数据库查询。

### 7.2 专题组件会同时发起外部请求

一个专题包含多个 FRED 或 World Bank 组件时，打开页面会同时发起请求。当前模板规模较小，但后续应增加组件懒加载、请求去重和工作区聚合接口。

### 7.3 图表包仍较大

图表包 gzip 约 183 KB，已经按需加载，不影响本地使用；后续可以继续按图表类型拆包。

### 7.4 可访问性和视觉回归尚未完成实机审计

本次完成了代码级语义、焦点结构和旧版 Safari 兼容检查，但当前执行环境没有可用的浏览器截图控制接口，因此没有完成基于截图的多视口比较、全键盘路径和 VoiceOver 实机审计。不能把这一部分视为已经验收。

### 7.5 测试依赖未来升级

Starlette `TestClient` 存在弃用提示。建议在小版本中升级测试适配层并保持 API 回归不变。

## 8. 下一版本建议

建议下一步先做 v0.9.1「专题可用性增强版」，不要立即扩大到更多大型数据域。

优先级建议：

1. 增加专题工作区聚合 API，一次返回专题、时间线和项目摘要；
2. 专题组件按进入视口后加载，并对相同 FRED / World Bank 请求去重；
3. 证据篮增加按专题、来源、日期筛选和批量清理；
4. 允许在 UI 中编辑专题组件的序列、国家、指标、时间范围和变换；
5. 修复现券代码可信识别，并寻找字段更完整的可转债公开源；
6. 完成 1440×900、1280×800 和窄屏视觉回归，以及键盘和 VoiceOver 审计；
7. 消除 Starlette 测试弃用告警，增加冷启动与 50 个专题规模的性能基线。

完成这些以后，再考虑 v1.0 的稳定发布、专题模板分享或更深入的信用研究能力。
