# AKDesk Fixed v1.0.0：面向科技人员的 Vibe Coding 项目总结

## 1. 这份材料讲什么

AKDesk Fixed 的实际用户是保险集团下资管子公司的固收、宏观和信用业务人员。

这份材料面向科技同事，重点介绍：

- 如何通过 vibe coding 把业务想法持续演进为可运行产品；
- 产品为什么选择宏观固收和保险资管场景；
- 当前系统的技术栈、数据源、规模和质量边界；
- AI 编码没有替代哪些产品、业务和工程责任。

业务模块的浅显说明见 [v1.0.0 产品介绍](./AKDesk-Fixed-v1.0.0-产品介绍.md)。

## 2. 项目起点

项目从一个简单目标开始：

> 做一款类似 Wind、Qeubee 的个人免费行情资讯软件，以 AKShare / AKTools 一类公开数据能力为起点，并向固收增强方向发展。

随着实际使用和持续 review，目标逐步从“行情看板”演进为“市场观察 + 研究工作流 + 可信数据 + BYOK AI”的本地工作台。

这不是一次提示生成，而是持续重复以下闭环：

1. 产品负责人描述目标、问题或截图；
2. AI 编码代理阅读现有代码和数据结构；
3. 实现功能或修复；
4. 运行自动化、数据库和浏览器回归；
5. 根据真实运行结果继续修正；
6. 更新版本记录、用户文档和发布门禁。

## 4. 技术栈

### 前端

- React、TypeScript、Vite；
- 原生 CSS 设计系统；
- Recharts 和 Lucide 图标；
- Vitest 与 Testing Library；
- 单页应用和响应式 MacBook Air 布局。

### 后端

- Python 3.11–3.13；
- FastAPI、Uvicorn 和 Pydantic；
- SQLite、pandas 和 NumPy；
- AKShare、httpx 和 requests；
- pytest 与 Ruff。

### 本地运行与安全

- 服务只监听 `127.0.0.1:8765`；
- 用户数据保存在 macOS Application Support；
- FRED 和 AIHubMix Key 保存在 macOS Keychain；
- 生产依赖精确锁定；
- 发布包包含 CycloneDX SBOM、第三方声明、逐文件清单和 SHA-256。

## 5. 数据源

| 数据源 | 作用 | 持久化边界 |
| --- | --- | --- |
| AKShare | 中国资金、曲线、现券、国债期货、发行、转债、部分外汇 | 只做个人研究缓存，明确状态和时点 |
| FRED | 美国宏观、政策利率和美债序列 | 观测值按请求获取，不落 SQLite |
| World Bank WDI | 跨经济体结构比较 | 按许可署名并持久缓存 |
| GDELT | 外部事件发现 | 只缓存元数据，不缓存新闻全文 |
| AIHubMix | 用户自带 Key 的模型调用 | 对话不落库，页面只缓存最终摘要和元数据 |

公开数据降低了验证门槛，但没有机构级 SLA。产品用缓存、熔断、来源、观测时间、质量分和研究可用性门禁显式管理这一风险。

## 7. 质量基线

- 后端 149 项自动化测试，在 Python 3.11、3.12、3.13 各执行一遍；
- 前端 70 项自动化测试；
- schema 701、800、900、1100、1201、1301 的真实历史备份迁移到 1600；
- 300 秒稳态、59 轮核心 API 请求、0 次失败；
- 浏览器检查市场变化、每日复盘、每周复盘和外汇；
- 1280、800、640 三种宽度无横向溢出；
- 发布包排除用户数据库、缓存、备份、Key 和开发依赖。

这些结果证明当前门禁覆盖范围内的行为成立，不代表公开数据源具有生产 SLA，也不等于 24 小时或更长期生产稳定性证明。

## 8. Vibe Coding 带来的收益

- 自然语言需求可以快速变为可操作的软件；
- 截图问题可以直接进入“定位—修改—复拍”闭环；
- 同一个代理能同时处理前端、后端、数据库、测试、发布和文档；
- 在需求尚未完全标准化时，业务人员可以通过真实产品而不是抽象原型做判断；
- 低成本试错使市场、信用、宏观和 AI 场景能持续校准。

## 9. Vibe Coding 没有替代什么

- 业务负责人仍需决定产品目标、金融口径和风险边界；
- 数据许可、机构合规和生产责任不能交给模型判断；
- 公开数据异常必须由业务人员理解和核验；
- 自动化测试需要围绕真实失败不断补充；
- 发布、迁移、备份、依赖和安全必须显式工程化；
- AI 生成速度不能替代正式生产系统所需的架构治理、运维和审计。

项目中最重要的改进并不是“让 AI 多写代码”，而是把业务约束写进数据模型、UI 状态、服务逻辑和测试门禁。

## 10. 纯人工开发的人力估算

若由传统方式从零完成同等范围的可运行原型，并包含当前的多源数据、研究工作流、信用模块、BYOK AI、迁移、发布和文档，粗略估算：

| 角色 | 建议投入 |
| --- | --- |
| 产品经理 / 业务分析 | 1 人 |
| 固收 / 宏观业务专家 | 0.5–1 人 |
| 前端工程师 | 1–2 人 |
| Python 后端 / 数据工程师 | 1–2 人 |
| 测试工程师 | 0.5–1 人 |
| 设计师 | 0.5 人 |
| DevOps / 安全支持 | 0.25–0.5 人 |

合计约 4–7 个全职当量，较合理的原型周期约 6–10 个月；如果要求机构数据、权限、审计、桌面签名、公证、集中部署和生产 SLA，规模和周期还会显著增加。

该估算是对功能范围的工程量级判断，不是精确预算。vibe coding 缩短了实现和反馈周期，但项目负责人仍投入了持续的产品选择、真实运行观察和验收判断。

## 11. 在科技组织中的价值

AKDesk 更适合作为：

- 业务和科技共同定义需求的可运行样品；
- 保险资管投研工作流的创新试验台；
- BYOK AI 权限、上下文裁剪和用户确认机制的参考实现；
- 评估公开数据能做什么、不能做什么的边界样本；
- 后续采购、集成或自研正式系统前的需求澄清工具。

它暂时不适合作为机构生产终端直接推广。进入机构试点前，应优先补齐数据授权、桌面交付、权限审计、集中运维和更长稳态验证。
