# AKDesk Fixed v0.12.1「GDELT 事件雷达」

> 版本：v0.12.1  
> 目标：为专题与信用发行人研究增加可追溯、低频、按需的外部事件发现能力  
> SQLite schema：1201

## 版本定位

v0.12.1 增加的是“事件线索雷达”，不是通用新闻客户端，也不是自动舆情或信用风险评分。它使用 GDELT DOC 2.0 按检索词读取文章元数据，帮助个人研究者发现可能需要核验的事件，再由用户打开原文、交叉核验并决定是否进入研究项目。

## 核心流程

```mermaid
flowchart LR
    A["专题或发行人"] --> B["按需检索 GDELT"]
    B --> C["标题、链接、来源、语言、时间"]
    C --> D["打开原文人工核验"]
    D --> E["加入证据篮"]
    E --> F["提交到研究项目"]
    F --> G["进入专题时间线与复盘"]
```

线索在加入证据篮前不会成为项目证据；加入证据篮后仍标记为 `unverified_clue`。只有用户选择目标项目并提交，才会进入研究时间线，事件类型显示为“GDELT 线索”。

## 专题事件组件

“专题设置 → 添加组件”新增“外部事件雷达”，支持：

- 检索词：2–200 个可见字符；
- 回看范围：1–90 天；
- 返回数量：5–50 条；
- 排序：最新优先或相关性优先；
- 组件级刷新；
- 标题、来源域名、来源国家、语言和本机时间展示；
- 单条线索加入当前专题证据篮。

建议优先使用：

- 发行人或机构的明确英文名；
- 加引号的完整短语；
- 经过理解后使用的 GDELT 查询操作符。

宽泛检索词会增加噪声；同名主体必须通过原文确认。

## 信用观察联动

“信用观察 R2 → 发行人”新增事件观察入口。点击后会：

1. 以主体归一名创建或打开唯一发行人事件专题；
2. 自动配置 30 天、20 条、最新优先的事件组件；
3. 保留项目摘要与最近证据组件；
4. 重复点击打开同一专题，不制造重复研究对象。

该入口不会自动建立评级、违约概率、主体分数或研究结论。

## 缓存与限流

GDELT 连接器采用适合 MacBook Air 和个人研究的轻量策略：

- 只在用户打开组件、主动刷新或重试时请求；
- 相同检索在 12 小时内复用 SQLite 缓存；
- 远端请求之间至少间隔 5 秒；
- 单次最多保存 50 条；
- 单条查询缓存上限 512 KB；
- 远端失败且存在缓存时显示过期缓存与明确警告；
- 连续失败 3 次后短时熔断，避免反复冲击公开端点。

新增表：

```text
gdelt_query_cache
```

保存查询参数、规范化文章元数据、抓取时间和过期时间。正式库升级前已生成：

```text
data/backups/before-v0.12.1-20260723.db
```

## 数据与版权边界

本地只缓存：

- 查询词；
- 标题；
- 原文 URL；
- 来源域名；
- GDELT 看到文章的时间；
- 语言和来源国家；
- 可选的社交图片 URL；
- 抓取、许可和署名元数据。

应用不抓取或保存新闻正文，不绕过登录、付费墙或原网站访问限制。研究证据也只保存引用元数据。使用时应保留 [The GDELT Project](https://www.gdeltproject.org/) 署名并阅读其 [使用说明](https://www.gdeltproject.org/about.html)。

## 已知限制

- 新闻覆盖受国家、语言、媒体生态和 GDELT 收录范围影响；
- 匹配标题可能重复、误配同名主体或缺少关键上下文；
- 来源国家不等于事件发生地；
- “文章数量”不代表风险强度或事实可信度；
- 本版本不做正文摘要、实体消歧、情绪分数、事件聚类或自动预警；
- GDELT 公共 API 可能限流，限流时应等待或使用已有缓存。
