# AKDesk Fixed v0.7.0.1「可信收口版」

> 适用版本：v0.7.0.1  
> 发布定位：v0.7.0 的可信边界、工作流和回归测试收口

## 版本目标

v0.7.0.1 不扩大数据覆盖，而是让 v0.7.0 已有的研究、发布复盘和信用观察更可信、更可控。核心原则是：来源不合格时不辅助计算，重复操作不制造脏数据，已保存内容可以修改，关键工作流必须经过接口级回归。

## 主要更新

### 1. 信用候选严格门禁

信用观察中的“现券候选”和“国债基准曲线”现在分别校验：

- 不是演示数据；
- 缓存没有过期；
- 具有明确观察日期；
- 可信等级为 `trusted`；
- 质量分不低于 80。

任一条件不满足时，页面会禁用对应的带入功能，并显示可信等级、质量分和具体阻断原因。系统不会把候选行情包装成评级、主体或到期日来源，这些字段仍须用户人工核验。

### 2. FRED 证据边界加固

FRED 证据不再只依赖来源摘要是否以“FRED”开头。服务端会同时检查来源摘要、结构化 provider/source/adapter 字段和 FRED 官方 URL；一旦识别为 FRED：

- `storage_mode` 必须为 `reference_only`；
- 只能保存序列、来源、区间、变换和 vintage 引用；
- 递归拒绝 `value`、`values`、`observations`、`actual_value`、`data_points` 等观测值字段。

FRED 实际值继续只在用户请求期间处理，不写入 SQLite。API Key 仍只保存在 macOS Keychain 或开发环境变量中。

### 3. 一键立项幂等与直达

从行情、自选、市场线索或信用观察创建研究项目时，系统会记录“模板 + 对象类型 + 对象标识”的来源映射。同一对象重复点击会复用已有的未归档项目，不再重复建项。创建成功后可直接点击“打开项目”进入对应研究页。

已归档项目不会阻止重新立项；再次立项会生成新项目并更新来源映射。

### 4. 发布复盘与信用观察可维护

数据发布复盘新增：

- 编辑已保存预期；
- 复制既有复盘作为新记录；
- 选择序列时辅助填入中文名称和单位，并展示目录频率；
- 空清单引导、取消编辑和请求失败反馈。

信用观察新增：

- 编辑主体、评级、期限、收益率、基准和来源字段；
- 中文覆盖字段与缺失原因；
- 无观察对象时隐藏没有意义的 `0/0` 覆盖卡片；
- 删除、编辑失败的明确反馈。

债券代码与名称是观察记录的稳定标识，编辑状态下不可修改；需要变更标识时应删除后重新建立。

### 5. 可访问性与中文化

- 研究记录类型选择器增加可访问名称；
- 文件导入控件退出键盘焦点顺序，由具名按钮触发；
- 市场线索敏感度字段改为中文业务名称；
- 自选页的市场状态和可信等级改为中文显示。

## 数据库升级

SQLite schema 从 `700` 升级到 `701`，仅新增 `research_project_origins` 项目来源映射表。启动时自动执行幂等迁移，不删除既有研究项目、研究记录、证据、自选、提醒、发布复盘、信用观察、日报或市场历史。

建议升级前关闭旧版本进程。启动 v0.7.0.1 后，可在“数据健康”确认应用版本，并在“研究项目”执行一次整库备份。

## 回归结果

- 后端：79 项通过；
- 前端：16 项通过；
- TypeScript 类型检查与 Vite 生产构建通过；
- HTTP 集成测试覆盖研究模板幂等、研究记录、FRED 证据拒绝、信号设置、自选、信用观察、发布复盘、每周复盘、项目导入导出和数据库备份恢复；
- 备份恢复后 SQLite 完整性与 FRED 观测值不落盘边界保持有效。

## 保持不变的边界

- AKShare/AKTools 为公开数据接口，不是交易所授权实时行情；
- 信用观察只做字段覆盖校验和同日、同期限机械利差试算，不输出内部评级、违约概率或投资结论；
- FRED 观测值不做应用级持久化或离线缓存；
- World Bank、主权横向比较、组合持仓和多人协作不在本版本范围；
- 本软件面向个人研究，不应作为下单、估值入账或风控限额的唯一依据。
