# AKDesk Fixed v1.1.0「GitHub 自助体验版」优化方案

> 设计日期：2026-10-21
> 状态：已按此范围实施，交付和验证状态见[发布与验收记录](./AKDesk-Fixed-v1.1.0-发布与验收记录.md)。本文保留设计时的范围、假设与估算，不将其当作实际工期或用户验证结果。
> 基线：v1.0.0；主要获客渠道：GitHub；发布后的实验观察期：4 周。

## 1. 版本决策

本版围绕一条路径建设：访客看到一页固收简报 → 直接打开在线演示 → 核验一条曲线变化 → 导出示例简报 → 下载本地版或提交反馈。

对外定位：

> AKDesk：把资金、曲线与国债期货变化整理成一页带出处的固收简报。

补充说明：基于 AKShare 的开源固收与宏观研究工作台，提供浏览器示例体验和 macOS 本地使用。

v1.1.0 是新增体验入口的小版本。原有研究项目、信用观察、全球数据和 BYOK AI 继续保留，本版优先改进发现、体验、启动和反馈路径，计划保持现有数据库 schema。

## 2. 用户与待验证假设

首批对象为关注债券、宏观与 AKShare、愿意尝试开源工具的个人研究者和金融开发者。保险资管业务人员仍是长期场景方向，当前不把其工作环境和使用意愿当作已验证前提。

本版验证三个假设：

1. 一份具体简报比完整功能列表更容易让 GitHub 访客理解用途；
2. 先体验结果再安装，会提高尝试本地版的意愿；
3. 一条完整任务路径可以带来具体反馈和再次使用。

Star、Clone 和下载反映关注或尝试，不能直接证明真实使用与留存。

## 3. 当前证据与工程约束

- 最近核验时，仓库为 0 Star、0 Fork，正式 ZIP 下载为 0，尚未发现外部用户的有效反馈；最近 14 天访问样本极小，不能据此认定需求失败。
- 整个前端应用依赖 FastAPI。`api.ts` 使用 `/api/v1`；应用启动还读取健康、自选、提醒和 AI 状态。整个前端不能直接放到静态站点作为完整产品运行。
- 市场变化默认只展示 `actionable` 信号，而后端对演示数据设为不可行动。直接把示例塞进现有页面，默认会得到空列表。
- 当前日报已有 Markdown 和打印导出，可复用；逐源出处、时间口径和示例标识还需要在新简报模板中补齐。
- Vite 还没有针对项目站点配置子路径；正式前端产物位于 `frontend/dist`，演示构建必须隔离。
- 2026-10-18 的一个 Dependabot PR CI 显示后端 4 项失败、145 项通过。失败用例使用固定 7 月日期查询最近 30/45 天历史，与当前日期产生耦合；应在本版实现时修复并复测。该日志本身不代表真实行情功能故障。

## 4. 范围与优先级

| 编号 | 优先级 | 交付项 | 用户得到的结果 |
| --- | --- | --- | --- |
| G01 | P0 | 恢复测试与运行基线 | 当前版本可以被可靠地安装、验证和维护 |
| G02 | P0 | 三视图静态在线演示 | 无安装、无登录、无 Key 即可完成体验 |
| G03 | P0 | 一页固收简报与导出 | 在网页内看见并保存一份完整成果 |
| G04 | P0 | README、项目站点和下载入口重构 | 首屏理解用途，清楚选择体验或本地使用 |
| G05 | P1 | macOS 启动预检与脱敏反馈 | 遇到安装或连接问题时能给出有用反馈 |
| G06 | P1 | 60 秒演示与可复现 AKShare 案例 | 从相关生态进入并快速理解产品 |

P0 为发布门禁。P1 原则上同版交付；若被第三方投稿审核等外部因素阻塞，发布时注明其真实状态，不以未获收录阻塞产品发布。

### G01：恢复测试与运行基线

- 为历史时间窗口用例提供可控时钟或明确测试锚点，使测试结果不随真实日期推移而失效；保留真正的窗口边界断言。
- 审核现有依赖升级 PR，按必要的安全和兼容性变化更新锁文件、SBOM 与第三方说明，并逐项回归。
- 在隔离数据目录中检查核心资金、曲线、期货、日报和健康状态；区分未配置、上游故障、缓存和演示。
- 确认当前 FRED/AI 配置可选，未配置时核心体验可以完成。
- 重新执行支持版本的后端、前端、启动停止与洁净发布检查。

验收：完整 CI 恢复通过；失败源有明确状态；正常数据与异常状态都可验证；测试不依赖“现在仍然是 2026 年 7 月”。

### G02：三视图在线演示

演示只保留：市场变化、曲线核验、一页简报。入口从市场变化直接开始，提供三个步骤的任务提示。

- 页面持续显示“固定示例数据 · 非实时”和固定样例日期；导出也保留标识。
- 可切换视图、筛选示例变化、查看来源说明、查看期限利差、导出简报、一键重置。
- “下载 macOS 本地版”和“反馈这个体验”始终容易找到；展示演示与完整本地版的功能差异。
- 示例默认可见；示例不使用真实数据的“可信可行动”资格或分数来暗示已验证行情。
- 所有示例为仓库内可审查的合成 fixture，不读取生产数据库或个人研究资料，不请求外部行情与 AI。
- 演示设置使用独立存储前缀，不与本地版共享偏好语义。

验收：打开无需安装、登录和 Key；加载后可完成“变化→曲线→简报”；无 `/api/*` 或上游行情、AI 请求；固定日期及示例标识一致；刷新、浏览器前进后退和子路径访问正常。

### G03：一页固收简报

模板按以下内容组织：

1. 日期、样例/真实模式、观测区间及生成时间；
2. 资金：核心利率和 BP 变化；
3. 曲线：10Y、10Y–1Y、关键期限变化；
4. 期货：TS/TF/T/TL 的方向与日变化；
5. 待核验事项与数据缺口；
6. 逐源出处、观测时间、抓取时间及状态；
7. 本机临时填写的人工备注。

导出支持 Markdown 和浏览器打印/PDF。页面是紧凑的一页摘要，常规示例在 A4 横向打印预览中以一页呈现；较长备注允许自然分页，不以裁切内容强行凑一页。首个版本不依赖 AI。

本地版使用相同模板读取现有日报数据；缺失内容保留为空或显示不可用。示例版使用同构 fixture。人工备注默认在当前页面处理，不增加研究库迁移。

验收：页面与导出数值一致，BP/% 单位正确，出处与时间完整，示例字样不丢失；缺失值不输出为 0；打印无截断。

### G04：GitHub 入口重构

README 首屏顺序：一句任务价值 → 简报成品 → 在线体验 / 下载两个主要入口 → 60 秒演示 → 最短安装步骤 → 反馈。完整能力、历史版本和发布工程说明向后组织。

- 中英文均提供价值说明、支持系统和体验入口；业务界面本版仍以中文为主，避免暗示已完整国际化。
- 项目站点首页提供简报预览、在线演示、系统要求、下载和 FAQ。
- 明确 macOS 本地版的 Python 要求；其他系统用户可访问静态体验，不宣称正式支持其本地运行。
- GitHub About 的 Homepage 指向站点；Topics 围绕 AKShare、fixed-income、macroeconomics、financial-data 等真实内容选择。
- Release Notes 展示改进结果、下载步骤、兼容范围和已知限制；保留正式 ZIP、校验值与版本化发布记录。
- 把已过期的投票更新为带日期的历史结果，新的反馈入口只保留少量可回答问题。

验收：所有入口和文档链接可访问，视频实际可播放，在线演示与下载版本清晰对应，安装说明不混用源码包和正式包。

### G05：启动与反馈

沿用已有 #17、#18 的意图，但缩小到本版所需范围：

- 启动时明确 Python、端口、依赖、证书和数据目录检查结果；给出针对当前错误的恢复动作。
- 从“关于/帮助”和错误页进入反馈，预填版本、页面、演示/本地模式。
- 用户可主动预览、复制脱敏诊断摘要；不自动上传，不默认填写个人路径、Key、研究正文或数据库内容。
- “成功启动”和“再次使用”反馈均为自愿提交，不能把一次按钮点击视为已提交或已留存。

验收：至少覆盖缺少 Python、端口占用、证书/依赖失败和本地服务不可连接；诊断输出经过样例秘密值与个人路径的脱敏检查。

### G06：可复现案例与真实视频

- 录制一段 60 秒成片，展示市场变化、曲线和简报导出；使用固定示例，字幕标明非实时。
- 编写《用 AKShare 生成一页固收市场简报》案例，包含接口与字段、BP 计算、时间口径、失败处理和输出样例。
- 提供最小可运行命令与固定示例模式；实时模式按需访问 AKShare，运行时不要求 FRED/AI Key。
- 在本仓库发布案例与示例输出后，再评估申请 AKShare 相关文章栏目收录。其栏目确实展示第三方案例，但投稿流程和是否接受 AKDesk 仍需维护者确认。
- 外部 PR、帖子或给维护者的消息先形成具体内容，再按用户授权范围执行；实现本方案不自动表示已完成外部收录。

## 5. 技术落地

建议在现有 React 工程中增加独立 `DemoApp` 入口，通过明确数据参数复用图表、格式化和展示组件，不挂载整个 `App`，也不模拟整套后端 API。

```text
共享展示组件与简报渲染
├── 本地 App → FastAPI → 真实数据 / 缓存 / 明确降级
└── DemoApp  → 固定合成 fixture → 静态页面
```

- 演示构建产物为 `frontend/dist-demo`；正式 `frontend/dist` 保持独立。
- fixture 生成时固定日期、来源说明和模式。现有 `demo_data.py` 可提供数值思路，但其中动态 `date.today()` 不直接作为公开演示日期。
- 项目站点采用 `/akdesk-fixed/` 基础路径和 hash 路由；图标、分块脚本与导出链接都经过子路径检查。
- 部署使用 GitHub Pages 静态产物及独立 Actions 工作流。构建时只上传站点目录，避免把整个仓库作为网站产物。
- 公共演示无需托管 Python 后端，运行开销主要是静态资源；公共静态站点不提供实时行情云服务。
- 本版不默认引入访问追踪 SDK。GitHub 仓库 Traffic 与 Pages 访问不是同一统计，不能据仓库访问推算演示完成率。

## 6. 验收与验证矩阵

| 范围 | 必须验证 |
| --- | --- |
| 后端 | Python 3.11–3.13；原有数据可信和历史窗口测试；依赖完整性 |
| 前端 | 原有测试、lint、类型、构建；共享渲染与计算回归 |
| 演示 | 无后端依赖；固定日期；示例标识；无上游/AI网络调用 |
| 路径 | `/akdesk-fixed/` 资源加载；hash 深链接刷新；前进后退 |
| 视口 | 1440×900、1280×800 与窄屏 390×844；核心操作可达 |
| 导出 | 页面与文件一致；来源、单位、时间和模式完整；打印无裁切 |
| 本地运行 | 全新安装、重复启动、Control+C、独立停止器、现有数据库兼容 |
| 发布 | 版本一致；锁文件和 SBOM 同步；洁净 ZIP；校验值；演示与本地产物隔离 |

性能以固定环境下的构建体积和浏览器测试记录为依据；目标为常见宽带下数秒内可操作，不把不同地区访问 GitHub 的网络差异归为产品执行性能。

## 7. 实施顺序与交付物

建议按依赖顺序完成，同一 v1.1.0 发布：

1. 恢复运行与测试基线，确认可复用的数据和展示边界；
2. 提取简报渲染并完成固定示例、三视图演示和独立构建；
3. 完成本地启动/反馈入口、README 与项目站点；
4. 录制视频，完成案例与发布回归，发布 v1.1.0。

初步估算为 10–15 个开发工作日，包含设计、实现、回归、视频和案例；估算尚未经过完整依赖及上游接口排查，不作为交付日期承诺。外部投稿审核不计入开发工期。

最终交付：新版源码与正式包、在线示例站点、一份示例简报、60 秒成片、中英文快速开始、可复现案例、诊断反馈入口、发布回归记录。

## 8. GitHub 内推广与四周实验

发布前完成可体验的内容，再以 Release、README、About/Homepage、置顶公告和相关案例互链承接访问。每周只维护一篇案例与一条核心路径，反馈按可复现问题、场景建议和使用问答处理。

发布后每周手工记录：仓库 Traffic、来源、正式 ZIP 下载增量、非机器人反馈、明确启动成功、明确七日复用。排除维护者测试和已知机器人；未识别流量保留为未知。

四周初始实验门槛：至少一个 14 天统计窗口达到 30 名仓库独立访客、3 位外部用户主动确认启动或完成任务、2 位用户主动确认七日内再次使用。不同周的独立访客不直接相加。这些是方向判断门槛，不是增长预测，也不足以证明产品市场匹配。

| 观察 | 下一步 |
| --- | --- |
| 有效触达仍很少 | 改进相关案例与项目发现，继续观察曝光 |
| 有访问但没有明确尝试 | 检查价值表达、演示效果与系统门槛 |
| 有尝试但启动失败 | 优先修复安装和错误恢复 |
| 有成功使用但无复用 | 检查简报是否解决持续任务，再调整场景 |
| 有复用与具体需求 | 围绕同一路径迭代 v1.1.x |

本方案不新增默认遥测，因此不会获得完整的访问→体验→安装→复用自动漏斗。实际使用依赖自愿反馈；GitHub 指标只能提供部分线索。

## 9. 本版边界

本版不扩展新资产类别、AI 模型、交易能力、多人协作或完整 Windows/Linux 支持；不把整个研究工作台搬到云端；不批量增加无明确维护者规则的推广 PR。后续范围由真实使用证据决定。
