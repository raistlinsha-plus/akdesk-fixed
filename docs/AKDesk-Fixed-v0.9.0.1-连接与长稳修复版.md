# AKDesk Fixed v0.9.0.1「连接与长稳修复版」

> 发布日期：2026-07-17  
> 升级性质：v0.9.0 稳定性热修复  
> 数据库 schema：900（无迁移）

## 1. 版本目标

v0.9.0.1 不扩展产品模块，专门修复连接生命周期和长时间运行稳定性。它解决一种容易被误认为“休市导致数据不可用”的问题：服务运行和查询次数增加后，本地 SQLite 文件句柄可能持续累积，最终使正常的研究库或行情缓存读取失败。

市场休市只会影响“交易中、已收盘、非交易日”和数据时效标签；只要存在合格的最近快照，休市本身不会让数据连接变为不可用。

## 2. 根因与影响

Python 的 `sqlite3.Connection` 上下文管理器只负责提交或回滚事务，并不会在退出 `with` 后关闭连接。v0.9.0 的主研究库和持久行情缓存把它当作完整连接上下文使用，因此文件句柄只能等待垃圾回收释放。

这会产生三个影响：

- 查询次数越多，未及时回收的数据库句柄越多；
- macOS 双击启动的进程可能使用较低的文件句柄软上限；
- 达到上限后，缓存读取、健康检查和数据请求可能连锁失败，并显示为“数据不可用”。

## 3. 本版修复

### 3.1 SQLite 连接确定性释放

- 主研究库所有读写操作在提交或回滚后立即关闭连接；
- 持久行情缓存所有查询、写入、清理和统计操作立即关闭连接；
- 数据库初始化、下载备份、恢复和完整性校验的源连接与目标连接均显式关闭；
- 保留原有 WAL、外键约束、忙等待和事务语义。

### 3.2 长稳回归

新增专门的文件描述符测试：关闭 Python 自动垃圾回收后，连续执行 120 次研究库查询和 120 次行情缓存查询，确认文件句柄不随查询次数增长。这个用例会直接捕获“依赖垃圾回收关闭连接”的回归。

### 3.3 本机资源诊断

`/api/v1/info` 现在返回：

- 当前服务 PID；
- 服务运行时长；
- 活跃线程数；
- 已打开文件句柄数；
- 文件句柄软上限、硬上限和当前占比。

数据健康中心会显示这组信息，方便区分“外部数据源异常”和“本机运行资源异常”。不支持进程句柄计数的平台会安全显示为空，不影响服务。

### 3.4 后台轮询治理

- 全局数据健康和未读提醒在浏览器页面进入后台后暂停自动轮询；
- 页面回到前台时立即同步一次，然后恢复固定间隔；
- 数据健康中心自动刷新间隔由 5 秒调整为 15 秒；
- 手动同步、单源重试和清空缓存行为保持不变。

这可以减少 MacBook Air 长时间挂在后台时的无效 HTTP 请求、SQLite 查询和系统唤醒。

## 4. 升级说明

直接停止旧版服务后，双击 `start-macos.command` 即可。启动器会校验 v0.9.0.1 服务版本。

本版不修改 schema，不会迁移或删除专题、项目、证据、自选、提醒、市场历史、World Bank 缓存和 FRED Keychain 凭据。升级前仍建议按用户手册下载一次研究库备份。

## 6. 用户如何判断是否正常

打开“数据健康”，先看两组信息：

1. 数据源的连接状态、研究可用性、观测时间和错误信息；
2. 页面顶部的文件句柄数量及占比。

休市时看到“已收盘、非交易日、缓存可用或受限可用”通常是正常状态。若某个数据源显示不可用，优先执行单源重试；若多个来源同时失败，再检查网络、代理和本机运行资源。
