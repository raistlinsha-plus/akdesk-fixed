计数规则：

- GitHub Traffic 的唯一访客按其14天口径记录，重叠窗口不相加。仓库访客不是 Pages 体验完成数。
- 下载只记录版本化正式 ZIP；Source code、机器人、维护者验收下载和无法归属的访问分开备注。
- “任务完成”和“再次使用”须用户主动表达，不以Star、Clone或按钮点击代替。没有反馈应写“未观察”，不假定为0实际用户。
- 不记录岗位之外的身份、联系方式、私人文件、Key或未公开业务资料。反馈链接只指向公开且已脱敏的Issue/Discussion。
- 每次调整只围绕一条体验路径，先修可复现阻塞。四周后按[路线图](../ROADMAP.md)判断下一步；实验门槛不是增长预测。

可以直接回答的三个问题：你要完成什么任务？在哪一步停住？下周是否还会用这份简报、为什么？
