# AKDesk Fixed v0.9.2「专题规模与交互增强版」

> 发布日期：2026-07-17  
> 升级性质：专题规模、长时间线与组件容错增强  
> 数据库 schema：900（无迁移）

## 1. 版本目标

v0.9.2 承接 v0.9.1 已完成的专题聚合、懒加载和配置编辑，解决专题资料逐步积累后的三个日常问题：专题多时难找、单个外部组件失败时缺少局部恢复手段、长时间线一次展示过多。版本不扩大数据域，重点提升 50+ 专题和长时间线下的可用性。

## 2. 专题库规模优化

专题列表不再为每个专题单独查询关联项目。后端先一次读取专题与研究对象，再一次批量读取全部关联项目，并在内存中按专题分组。无论返回 1 个还是 50 个专题，列表读取都只占用一个 SQLite 连接。

`GET /api/v1/research/topics` 新增：

- `q`：搜索标题、研究问题、说明、标签和研究对象名称；
- `status`：筛选持续跟踪、待专题复盘或已归档；
- `limit`：1–500 条，默认 200 条。

前端一次读取最多 500 个本地专题，并提供即时搜索、状态筛选和匹配数量。空库与无匹配结果使用不同提示。

## 3. 组件级刷新与失败重试

以下远程组件新增独立刷新按钮：

- 当前市场脉搏；
- 本地市场历史；
- FRED 图表；
- World Bank 主权比较。

首次读取和刷新都显示组件自己的加载状态。某个数据源失败只在对应组件显示错误；点击组件右上角刷新即可强制重试，不会重新加载整个专题、其他图表、项目摘要或证据篮。

强制刷新会绕过前端短时内存缓存。若旧请求与新请求并发，只有最新共享请求可以更新缓存，避免旧响应覆盖刷新结果。FRED 观测值仍只存在于请求和前端内存中，不写入 SQLite 或浏览器持久存储。

## 4. 长时间线筛选与分批显示

专题聚合接口最多读取 300 条时间线记录。页面支持：

- 搜索标题、摘要和项目名称；
- 按数据与证据、研究记录、项目变化、发布复盘分类；
- 按关联研究项目筛选；
- 每次显示 20 条，按需继续加载。

修改专题或任一筛选条件后，显示数量重置为前 20 条。筛选只改变视图，不修改本地研究记录。

## 5. 键盘与状态语义

- 专题列表使用原生按钮，暴露当前选择状态；
- 专题和时间线使用列表语义；
- 搜索结果数量通过状态区域播报；
- 切换专题后，键盘焦点移动到新专题标题区域；
- 延迟加载组件暴露忙碌状态，组件刷新按钮具有明确名称和禁用状态。

本版补齐代码层键盘语义和焦点路径；macOS VoiceOver 的逐页面实机审计仍应作为独立验收执行，不在文档中宣称已全部完成。

## 6. 升级说明

停止旧版服务后双击 `start-macos.command`。启动器会校验 v0.9.2。

SQLite schema 继续保持 900，不新增表、不改写专题配置，也不迁移现有数据。专题、项目、研究对象、证据篮、自选、提醒、World Bank 缓存与 FRED Keychain 凭据全部保留。

## 8. 后续建议

下一版本建议进入 v0.10.0「研究报告生产版」：把专题组件、项目摘要、时间线和引用证据组合成可编辑报告大纲，支持章节级 Markdown 导出与引用清单。并行的小范围可信任务可包括 macOS VoiceOver 实机审计、专题库虚拟滚动阈值和更细的时间线服务端游标分页；在实际专题量超过 500 前，不建议引入复杂搜索基础设施。
