# AKDesk Fixed：面向科技同事的 Vibe Coding 成果介绍

> 适用版本：v0.18.0「低门槛交付版」  
> 材料读者：保险集团及资管子公司的科技、数据、产品和数字化同事  
> 产品目标用户：保险集团下属资产管理公司的固收、宏观、信用及投研管理等业务人员  
> 材料目的：介绍这次 vibe coding 做出了什么、为什么选择 FICC 业务方向，以及技术如何被转化成可运行的业务产品

## 1. 先澄清两个角色

这份材料是给科技同事看的，但 AKDesk 不是一款以科技人员为最终用户的产品。

| 角色 | 在本材料中的位置 |
| --- | --- |
| 科技、数据、产品和数字化同事 | 了解和评估本次 vibe coding 成果，理解产品、技术和业务之间如何连接 |
| 保险资管业务人员 | 产品实际服务的用户，包括固收投资、宏观研究、信用研究、组合与投研管理人员 |
| 产品发起人 | 提出业务方向、持续判断优先级、观察实际运行结果并决定迭代内容 |
| AI 编码代理 | 根据自然语言目标完成分析、编码、测试、修复、文档和版本演进 |

当前 v0.18.0 的交付形态仍是单机、单用户、本地运行版本。这里所说的“面向保险资管业务人员”，指产品问题和工作流围绕这类用户设计，不表示它已经具备保险资管生产系统所需的机构数据授权、多人权限、审计和运维能力。

## 2. 一句话介绍成果

AKDesk Fixed 是通过持续 vibe coding 构建的一套本地宏观固收市场观察与投研工作台。

它把业务人员常见的研究过程组织成一条可运行、可追溯的路径：

```text
发现市场变化
  → 判断数据是否可信
  → 回到行情模块核验
  → 保存证据
  → 建立或更新研究项目
  → 记录观点、反证和任务
  → 每日 / 每周复盘
```

如果用科技团队熟悉的概念类比：

| 金融投研概念 | 科技领域类比 |
| --- | --- |
| 今日市场 | 系统状态总览 Dashboard |
| 市场变化 | 相对于上一状态的 diff + anomaly inbox |
| 数据健康 | 数据管道 observability 控制台 |
| 自选 | 订阅列表或关注对象 |
| 提醒 | 带冷却时间、静默时段和每日上限的监控规则 |
| 研究项目 | Issue、Decision Record 和实验记录的组合 |
| 证据篮 | 提交前的 staging area |
| 专题投研 | 围绕一个问题建立的长期 workspace |
| 每日 / 每周复盘 | Changelog、postmortem 和 retrospective |
| AI 洞察 | 只读取授权上下文的 scoped copilot |

## 3. 为什么选择 FICC 和保险资管方向

FICC 是 Fixed Income、Currencies and Commodities 的缩写，即固定收益、外汇和大宗商品。AKDesk 当前重点覆盖固定收益、外汇和宏观研究，没有把大宗商品作为核心模块。

选择这个方向，不是因为它最容易做，恰恰是因为它能检验 vibe coding 能否处理真正的业务复杂性。

### 3.1 数据不是“请求成功就可以使用”

固收和宏观数据有不同的：

- 交易时间；
- 发布频率；
- 观测时间；
- 抓取时间；
- 市场状态；
- 缓存期限；
- 来源可信度；
- 研究使用边界。

例如 LPR 是月度报价，Shibor 是定盘数据，现券可能是盘中列表，FRED 序列可能按月或按季发布。页面在交易时间打开，不代表所有数字都应该实时跳动。

### 3.2 产品不能把观察结果包装成确定结论

市场变化、信用利差和 AI 摘要都容易形成“看起来很专业”的伪精确结果。产品必须知道什么时候可以算、什么时候不能算、什么时候只能提示人工核验。

### 3.3 保险资管业务强调长期资金和过程责任

保险资管业务人员关注的不只是某个价格，还包括：

- 利率和信用风险；
- 久期与长期资金配置；
- 流动性；
- 收益稳定性；
- 资产负债匹配；
- 投资依据和过程留痕；
- 定期投后跟踪和复盘。

AKDesk 目前不计算正式资产负债匹配、偿付能力或组合风险，但围绕“观察—证据—观点—复盘”构建工作流，与保险资管的研究过程具有较强关联。

### 3.4 这是一个适合检验“业务理解 + 工程实现”的方向

如果只做一个通用聊天框或简单 CRUD，很难判断 AI 编码是否真正理解了业务。FICC 产品要求同时处理：

- 多源异构数据；
- 金融口径；
- 可信状态；
- 复杂交互；
- 本地数据持久化；
- 数据迁移和备份；
- AI 权限与安全；
- 长时间运行；
- 用户反馈驱动的视觉修复。

因此，AKDesk 也是一次“vibe coding 能否从原型走向可用产品”的完整实验。

## 4. 产品实际面向哪些业务人员

### 4.1 固收投资经理与交易支持人员

他们需要快速了解：

- 资金面是否收紧或放松；
- 收益率曲线是整体移动还是形态变化；
- 国债期货与现券是否出现方向差异；
- 哪些债券、转债或发行事件值得继续跟踪；
- 今天的市场变化是否足以改变已有判断。

AKDesk 为其提供市场变化、今日市场、资金面、曲线、现券、期货、自选和复盘入口，但不提供交易指令和成交功能。

### 4.2 宏观与利率研究人员

他们需要把国内固收市场和全球宏观环境联系起来，例如：

- 美国通胀和就业是否改变利率预期；
- 中美利率、人民币汇率和国内债市如何联动；
- 某项数据发布前后的观点是否得到验证；
- 一个宏观主题有哪些支持证据和反证。

AKDesk 提供 FRED、World Bank、外汇、专题投研、图表研究室、数据发布复盘和证据篮。

### 4.3 信用研究人员

他们关注：

- 某个发行人和债券的基础资料是否完整；
- 评级、收益率、基准和观察日期是否一致；
- 哪些变化需要人工确认；
- 信用观察如何进入研究项目和投后复盘。

信用观察 R2 支持 CSV / Excel 导入、历史观察、发行人主档、组合和事件线索，但不生成正式评级、违约概率或准入结论。

### 4.4 组合、产品和投研管理人员

他们更关注：

- 目前有哪些活跃研究项目；
- 本周观点和反证发生了什么变化；
- 哪些任务尚未完成；
- 哪些项目即将到达复盘日期；
- 研究结论是否有数据来源和时间边界。

AKDesk 通过研究首页、项目、行动助手、每日复盘和每周复盘，把分散的个人研究活动组织起来。

## 5. 它试图解决什么业务问题

公开金融数据并不少，业务人员的实际困难通常是：

- 数据散落在多个网页、接口、Excel 和终端里；
- 不同数据的时点和频率不同；
- 接口失败后，不容易判断看到的是最新值、缓存值、过期值还是演示值；
- 行情、来源、研究笔记、证据和结论被保存在不同工具；
- 看到异常后，没有顺畅地进入后续研究；
- 研究项目缺少反证、任务和复盘；
- AI 可以生成文字，但上下文、数据时点和写入权限不透明。

AKDesk 的目标不是复制一套专业机构终端，而是用产品化方式串联这些断点。

## 6. 四类业务任务入口

用户首次进入时，不需要先理解完整菜单，而是从任务出发。

| 入口 | 首先回答的问题 | 主要用户 | 典型动作 |
| --- | --- | --- | --- |
| 每日看市场 | 今天发生了什么？ | 固收投资、交易支持 | 看变化、核验资金和曲线、加入自选、生成复盘 |
| 利率与宏观研究 | 一个问题如何形成可验证研究？ | 宏观和利率研究 | 建项目、比较宏观数据、收集证据、更新观点 |
| 信用观察 | 某个发行人或债券有哪些需要确认的变化？ | 信用研究 | 导入数据、检查字段、观察单券和组合、建立任务 |
| 全球跨市场 | 国内债市与全球利率、汇率和主权数据如何联动？ | 宏观、配置研究 | 看外汇、FRED、World Bank、专题和发布复盘 |

顶部还可以切换“市场”和“投研”导航。入口只改变落地页和导航顺序，不会分裂数据、自选和研究资产。

| 模块 | 业务作用 | 使用场景 |

| 研究首页 | 汇总项目、待复盘、统一自选和数据准备度 | 开始一天研究或继续未完成事项 |

| 每周复盘 | 汇总项目变化、反证、任务和下周事项 | 形成稳定研究节奏 |
| 研究行动助手 | 根据项目缺口生成任务、反证或复盘草稿 | 不知道下一步验证什么时 |

### 7.3 信用观察 R2

“信用”在这里不是个人征信，而是债券发行人能否持续履约、相关字段和信用利差是否发生值得核验的变化。

模块支持：

- CSV / Excel 字段映射导入；
- 同一债券多个观察日的历史；
- 发行人主档；
- 自定义组合；
- 事件日历；
- 人工确认信号；
- 在日期、期限和基准都匹配时机械试算利差；
- 从发行人或信号进入研究项目。

典型流程：

1. 导入业务人员维护的债券观察表；
2. 检查评级日期、收益率日期和期限等字段；
3. 查看单券、发行人或组合；
4. 对异常建立核验任务；
5. 通过 GDELT 等来源寻找事件线索；
6. 人工确认后再写入研究记录。

系统不会自动生成内部评级、违约概率、投资准入或买卖建议。

### 7.4 通用效率与可信工具

| 模块 | 作用 |
| --- | --- |
| 全局搜索 | 搜索债券、期货、转债、外汇、FRED 指标和专题 |
| 统一自选 | 管理证券、外汇和宏观指标的分组、标签、备注与复盘日期 |
| 提醒 | 支持阈值、冷却时间、静默时段、每日上限和 macOS 通知 |
| 保存视图 | 保存现券、转债等页面的筛选条件 |
| 数据健康 | 展示连接、研究可用性、缓存年龄、失败、熔断和重试 |
| 发布就绪 | 检查数据库、迁移、备份和运行环境状态 |

只有健康、未过期的真实数据可以触发提醒。演示数据、可疑数据和过期缓存不会触发。

## 8. 科技同事需要了解的金融概念

### 8.1 债券

债券可以简化理解为一组约定好的未来现金流：发行人定期付息，到期归还本金。

需要先记住：

- 债券价格上涨时，在其他条件不变的情况下，收益率通常下降；
- 债券价格下降时，收益率通常上升；
- 票面利率写在合同条款里，市场收益率会随价格、期限和现金流变化。

### 8.2 收益率曲线

收益率曲线把同一类债券不同期限的收益率画在一张图上，例如 1 年、5 年、10 年和 30 年。

| 变化 | 简化含义 |
| --- | --- |
| 整体上移 | 各期限收益率普遍上升 |
| 整体下移 | 各期限收益率普遍下降 |
| 变陡 | 长端相对短端上升更多，或下降更少 |
| 变平 | 长短端收益率差缩小 |
| 倒挂 | 短端收益率高于长端 |

`10Y–1Y` 表示 10 年期收益率减去 1 年期收益率。

### 8.3 BP

BP 是 basis point，中文常说“基点”。

```text
1 BP = 0.01 个百分点
10 BP = 0.10 个百分点
```

例如 10 年国债收益率从 1.70% 上升到 1.75%，就是上升 5 BP。

### 8.4 资金利率

资金利率反映金融机构短期借钱的成本。

| 指标 | 简化理解 |
| --- | --- |
| Shibor | 上海银行间同业拆放利率，反映银行间无担保资金价格 |
| FR007 | 银行间质押式回购相关定盘利率 |
| FDR007 | 存款类机构间质押式回购定盘利率，常用于观察银行体系资金 |
| LPR | 贷款市场报价利率，更接近贷款定价参考，不是盘中交易行情 |

### 8.5 现券和国债期货

现券是已经发行并在市场交易的具体债券。

国债期货是以标准化国债组合为基础的期货合约：

| 代码 | 大致期限 |
| --- | --- |
| TS | 2 年 |
| TF | 5 年 |
| T | 10 年 |
| TL | 30 年 |

期货价格与收益率通常反向变化，但专业分析还需要考虑基差、可交割券、久期和资金成本。

### 8.6 可转债

可转债同时具有：

- 债券属性：票息、到期日和偿还安排；
- 股票属性：满足条件时可以转换成发行公司股票。

常见指标包括价格、转股价值、转股溢价率、双低值和到期收益率。

### 8.7 外汇

`USD/CNY` 表示 1 美元对应多少人民币。

产品区分：

- 人民币日频参考价；
- 全球外币对银行间 bid / ask 询价；
- 中间值和点差；
- 有无可信市场时间戳。

没有可信时点的报价可以用于页面观察，但不会自动进入研究历史或触发提醒。

### 8.8 信用利差

信用利差可以简化为：

```text
信用债收益率 - 相同期限的无风险或低风险基准收益率
```

AKDesk 只有在债券收益率日期、基准日期、期限和必要字段都满足门禁时才机械试算。这只是数据计算，不代表信用评级或违约概率。

## 9. 行情和研究数据从哪里来

### 9.1 中国市场行情

AKShare / AKTools 是访问层，背后连接多个公开页面和接口，不是交易所授权的实时行情专线。

| 模块 | 主要来源 | 基础缓存 TTL | 主要边界 |
| --- | --- | ---: | --- |
| Shibor | AKShare / Shibor | 30 分钟 | 定盘或日频数据 |
| FR / FDR | AKShare 独立回购利率适配器 | 30 分钟 | 单个扩展源失败不影响 Shibor |
| LPR | AKShare / LPR | 6 小时 | 月度报价 |
| 收益率曲线 | AKShare / ChinaBond | 1 小时 | 国债、国开债和政策金融债曲线 |
| 现券 | AKShare / Chinamoney | 60 秒 | 可能没有可信市场时间戳 |
| 国债期货 | AKShare / Sina Futures | 30 秒 | TS、TF、T、TL 近季合约 |
| 全球外币对 | AKShare / Chinamoney FX | 120 秒 | 缺时点时限制研究写入和提醒 |
| 人民币参考价 | AKShare / BOC / Sina | 6 小时 | 日频参考价 |
| 可转债 | AKShare / Eastmoney，失败时 Sina | 120 秒 | 备用源可能只有价格 |
| 国债发行 | AKShare / CNInfo | 6 小时 | 发行安排，不是交易行情 |

TTL 是应用再次主动拉取前的缓存时间，不等于上游数据一定在该时间内更新。

### 9.2 全球宏观和事件数据

| 数据源 | 用途 | Key | 本地持久化边界 |
| --- | --- | --- | --- |
| FRED | 美国利率、通胀、就业、增长和发布复盘 | 用户自己的 Key | 观测值不写 SQLite，只保存序列与来源引用 |
| World Bank WDI | 全球主权结构比较 | 不需要 | 指标和观测值缓存 7 天 |
| GDELT DOC 2.0 | 国家、主题和发行人事件线索 | 不需要 | 只缓存元数据 12 小时，不保存新闻正文 |
| AIHubMix | AI 助手和页面洞察 | 用户自己的 Key | 只缓存摘要和必要元数据；它不是行情源 |

## 10. 产品如何处理“可信数据”

公开数据源可能超时、限流、改版、返回空表或只提供低频数据。AKDesk 不把所有成功响应直接标成“可研究”。

每个市场数据集尽量保留：

- 来源；
- 观测时间；
- 抓取时间；
- 市场状态；
- live、latest、cached、stale 或 demo 状态；
- 质量评分；
- 缓存年龄；
- 降级和异常说明；
- 是否达到研究门槛。

失败时的策略是：

1. 优先返回有效缓存；
2. 缓存过期时显示最后真实数据，并尝试后台刷新；
3. 更新失败时继续保留最后真实值；
4. 从未取得真实数据时才使用演示数据；
5. 明确标出缓存、过期、降级或演示状态；
6. 阻止不可信数据进入提醒、研究历史和信用计算。

“市场未开盘”和“数据不可用”是两个不同状态。系统会区分未开盘、交易中、午休、收盘、非交易日和日频数据。

对科技同事而言，这部分可以理解为：产品不仅实现了接口适配，还把数据质量规则变成了用户可见的产品状态和业务门禁。

## 11. AI 是怎样嵌入业务场景的

AI 不是自动交易引擎，也不替业务人员承担投资责任。

产品提供：

- 顶部 AI 助手：产品向导、市场观察和研究教练；
- 页面 AI 洞察：今日市场、研究项目、信用观察和专题摘要；
- 研究行动助手：把项目缺口整理成任务、反证和复盘草稿。

关键设计包括：

- 默认关闭，逐模块授权；
- 支持仅手动、数据变化后、每日首次打开等触发方式；
- 发送前说明上下文范围；
- 只发送任务所需的裁剪摘要；
- 不发送数据库、完整行情表、附件正文或新闻正文；
- API Key 保存于 macOS Keychain；
- AI 不自动修改研究项目、信用数据或观点；
- 写入前必须由用户选择并确认；
- 已采纳行动可以撤销。

这一设计体现了项目对 AI 产品化的判断：真正有价值的 AI 不一定表现为对话，也可以在业务页面中按事件或频率生成可核验的辅助内容。

## 12. Vibe Coding 是怎样完成这个产品的

### 12.1 不是一次提示生成，而是持续迭代

整个过程大致遵循：

```text
业务方向与 PRD
  → 可运行 MVP
  → 实际使用和截图反馈
  → 功能 Review
  → 缺陷修复与回归
  → 下一版本规划
  → 新模块开发
  → 再次 Review
```

产品发起人持续提供：

- 业务定位；
- 版本目标；
- 使用感受；
- 真实截图；
- “数据不可用”“滚动异常”“Failed to fetch”等问题线索；
- 对市场与投研比重的判断；
- 是否引入外汇、FRED、World Bank、GDELT 和 AI 的产品选择。

AI 编码代理负责：

- 阅读和理解已有代码；
- 设计技术方案；
- 修改前后端；
- 构建数据适配器；
- 编写迁移；
- 增加测试；
- 启动本地服务并浏览器验收；
- 根据截图修复视觉问题；
- 更新 CHANGELOG、用户手册、产品介绍和评审记录。

### 12.2 版本演进不是单纯堆功能

| 阶段 | 代表版本 | 主要变化 |
| --- | --- | --- |
| 行情原型 | v0.1—v0.3 | 建立资金、曲线、现券、期货等基础页面，解决并发和数据状态 |
| 日常研究 | v0.4—v0.5 | 自选、提醒、日报、复盘和可信稳定性 |
| 投研工作台 | v0.6—v0.7 | FRED、研究项目、证据、市场线索、发布复盘和信用观察 R1 |
| 双入口与专题 | v0.8—v0.10 | 市场 / 投研双入口、外汇、主权比较、专题和驾驶舱 |
| 信用与外部数据 | v0.11—v0.12 | 信用观察 R2、发行人联动、连接器、GDELT 和低门槛体验 |
| AI 产品化 | v0.13—v0.14 | BYOK 助手、连接修复、运行预算、授权和页面洞察 |

当前 CHANGELOG 记录了 41 个正式版本或修复版本。大量小版本不是重复包装，而是用来处理数据可信、连接稳定、信用口径、视觉细节、迁移和交付等问题。

### 12.3 人机分工

这次实践并不是“AI 自主完成产品、人员无需参与”。

| 人承担的责任 | AI 编码代理承担的工作 |
| --- | --- |
| 选择业务方向 | 把目标拆成产品和工程任务 |
| 判断什么对用户有价值 | 快速实现候选方案 |
| 观察真实使用问题 | 定位代码和状态问题 |
| 决定口径和风险边界 | 把边界写入数据模型、UI 和测试 |
| 接受或否决版本 | 执行回归、修复和文档更新 |
| 对最终使用负责 | 提高实现速度和覆盖范围 |

Vibe coding 降低了把想法变成软件的成本，但没有取消产品判断、业务责任和测试验证。

## 14. 三段真实业务使用旅程

### 14.1 固收投资人员的每日观察

1. 打开“市场变化”；
2. 只看达到可信门槛的高优先级变化；
3. 进入资金面或曲线核验原始数据；
4. 检查来源、观测时间和抓取时间；
5. 把值得持续观察的对象加入自选；
6. 形成一条研究任务或更新已有观点；
7. 在每日复盘中保存事实和边界。

### 14.2 宏观研究人员的专题研究

1. 从问题或模板创建专题；
2. 添加国内市场、FRED、World Bank 或 GDELT 组件；
3. 把数据快照放入证据篮；
4. 检查后提交到研究项目；
5. 更新假设、结论、反证和待验证任务；
6. 使用 AI 综述整理分歧和缺口；
7. 在周度复盘中记录观点变化。

### 14.3 信用研究人员的观察流程

1. 导入 CSV 或 Excel；
2. 确认字段映射；
3. 检查关键字段完整性；
4. 查看单券、发行人和组合；
5. 只在门禁通过时查看机械利差；
6. 为异常建立人工核验任务；
7. 将确认后的信息写入研究项目。

### 15.1 自然语言可以驱动完整产品演进

成果覆盖的不只是代码生成，还包括：

- PRD 和版本规划；
- 前后端开发；
- 数据适配；
- 本地数据库设计；
- 测试和迁移；
- 浏览器验收；
- 视觉修复；
- 用户手册和汇报材料。

### 15.2 业务约束需要进入代码，而不是只写在提示词里

例如：

- 不可信数据不触发提醒；
- 日期和期限不匹配时不计算信用利差；
- AI 未授权时不发送；
- AI 草稿不自动写入项目；
- 演示数据不伪装成真实行情；
- 外部正文不落本地研究库。

这些约束分别进入了数据模型、服务逻辑、UI 状态和自动化测试。

### 15.3 Review 和真实使用仍然不可替代

项目多次通过实际运行发现问题：

- 交易时间外被误认为数据不可用；
- SQLite 文件句柄累积；
- AI 请求 `Failed to fetch`；
- 信用列表滚动和定位异常；
- 字号、换行、卡片拉伸和内边距问题；
- `Control+C` 无效或找不到原启动终端。

这说明 vibe coding 可以显著提高开发速度，但真实使用、截图反馈、全量 Review 和回归仍是产品走向可用的关键步骤。

### 15.4 快速原型和机构生产之间仍有距离

如果未来把 AKDesk 用于保险资管内部正式生产，还需要：

- 获得机构认可的数据源和授权；
- 统一身份认证、角色权限和职责分离；
- 多用户协作和审批；
- 不可篡改审计日志；
- 数据分级、脱敏、加密和保留策略；
- 集中部署、升级、监控、灾备和应急响应；
- 内部模型网关和模型治理；
- 与正式投研、组合、风险和文档系统集成。

## 18. 最终总结

AKDesk 的成果不只是“AI 写出了约 4.8 万行代码”。

更重要的是，它展示了一条可重复的方法：

```text
业务人员提出方向和持续判断
  + AI 快速完成产品与工程实现
  + 真实使用暴露问题
  + Review、测试和文档形成约束
  = 从业务想法逐步演进为可运行产品
```

产品选择了科技同事并不熟悉的 FICC 和保险资管方向，但这正好说明：vibe coding 的价值不是绕过业务知识，而是缩短“理解业务—构建原型—验证需求—继续迭代”之间的距离。
