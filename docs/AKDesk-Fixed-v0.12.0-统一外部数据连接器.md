# AKDesk Fixed v0.12.0「统一外部数据连接器」

> 版本：v0.12.0  
> 目标：把外部数据的访问、凭据、缓存、许可和研究边界整理为同一套可检查契约  
> SQLite schema：1100（本版本本身不新增迁移）

## 版本定位

v0.12.0 不是增加更多行情卡片，而是先解决多数据源并存后的可信治理问题。AKShare / AKTools、FRED、World Bank 原先各自表达健康、缓存和许可；本版增加统一连接器目录，让用户在一个页面回答：

- 这个来源当前能否连接；
- 当前数据能否进入研究；
- 是否需要本人 API Key，Key 存放在哪里；
- 哪些内容会保存在本地；
- 缓存多久、怎样限流；
- 使用时需要遵守什么许可和署名；
- 哪些判断超出了数据能力边界。

## 统一连接器

“数据健康”新增四张连接器卡片：

| 连接器 | 访问方式 | 本地保存 | 研究边界 |
| --- | --- | --- | --- |
| AKShare / AKTools | 公开端点，无统一 Key | 仅质量门后的市场缓存和本地历史 | 非交易所直连，不承诺逐笔或交易级实时性 |
| FRED | 用户自己的 API Key | 观测值请求级处理，不落盘 | 数据可能修订，发布复盘需记录 vintage |
| World Bank | 公开 API | CC BY 4.0 署名缓存 7 天 | 低频结构数据不能替代实时主权风险判断 |
| GDELT | 公开 API | 仅事件元数据缓存 | 媒体匹配是待核验线索，不是事实或风险评分 |

每张卡片同时展示：

- 连接状态与研究可用性；
- 凭据来源，但不返回明文；
- 数据能力；
- 保存模式和缓存记录数；
- 最近一次当前进程成功时间；
- 接口文档、许可、署名和请求策略；
- 产品明确不承担的能力。

## 接口

新增：

```text
GET /api/v1/connectors
```

返回统一、无敏感凭据的连接器目录。前端不再需要从各数据服务的私有状态推断许可或存储方式。

原有：

```text
GET /api/v1/sources/health
```

继续保留逐适配器运行状态，用于单源重试、熔断、延迟和质量检查。两层含义不同：

- 连接器：面向用户的提供方、许可与存储契约；
- 适配器：面向运行诊断的具体数据任务。

## 安全与隐私

- FRED Key 仍只保存在 macOS Keychain 或环境变量中；
- 连接器接口只返回 `configured` 和 `credential_source`；
- API 响应、SQLite、日志和文档不包含 Key 明文；
- “清空缓存”明确列出会删除的提供方缓存，不删除项目、证据、自选、提醒和复盘归档。

## 升级与回退

v0.12.0 不引入新表。升级到 v0.12.1 后 schema 会升至 1201；如需整体回退，应使用升级前的 SQLite 安全副本，而不是让旧版本继续写入 schema 1201 数据库。

## 后续关系

v0.12.0 提供治理底座，v0.12.1 在同一契约上接入 GDELT 事件雷达。TradingEconomics、Alpha Vantage 等后续来源应先满足同一连接器字段，再进入产品界面。
