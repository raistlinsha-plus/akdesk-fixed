# AKDesk Fixed v0.11.0「信用观察 R2」

> 发布定位：从严格单券试算升级为可持续维护的个人信用观察工作台  
> 适用设备：Apple Silicon MacBook Air，推荐 1440×900 或更高  
> 数据库版本：SQLite schema 1100，由 schema 900 自动幂等迁移

> v0.11.0.1 校准：修复空白可选列导入，默认先展示观察结果，发行人/组合改用单券利差范围，并增加当前观察 CSV 导出；schema 仍为 1100。

## 版本目标

信用观察 R2 用于整理用户已经核验的信用资料，并回答四类问题：当前观察哪些债券和主体、字段是否足够可信、机械利差如何变化、下一项需要人工复核的事件是什么。

它不是评级系统，不生成违约概率、内部评级、授信结论或买卖建议。

## 三级观察

### 单券

- 保存债券、主体、评级、到期与回售、收益率、基准和来源；
- 严格检查债券与基准是否同日、剩余期限与基准期限是否匹配；
- 展示最新机械利差、较上期变化、本地历史分位和历史期数；
- 保留多期收益率、评级和来源快照，并可一键创建信用研究项目。

### 发行人

- 按“主体归一名”聚合同一发行人的多只债券；
- 汇总评级记录、通过质量门的债券数、可比单券机械利差范围、样本数和下一事件；
- 行业、地区和主体类型均来自用户录入，不由系统猜测。

### 自定义组合

- 用户可以创建本地观察组合并维护成员；
- 汇总债券数、主体数、通过门槛数量和可比单券机械利差范围；
- 不记录仓位，不计算收益，不输出组合信用评分。

## CSV / Excel 批量导入

支持 `.csv`、`.xlsx` 和 `.xlsm`，单次最多 500 行、10 MB。

导入分为两步：

1. 选择文件后先自动识别常见中英文表头；
2. 用户检查或修改字段映射，逐行预览校验结果，再确认写入。

CSV 支持 UTF-8 与 GB18030。可以从页面下载标准模板。缺少来源、评级日期、收益率日期或基准的记录不会被补造；记录可以进入观察清单，但不能通过机械利差门禁。

v0.11.0.1 起，可选的“基准期限”列即使存在空单元格也会被识别为缺失值，不再阻断整批导入。页面还可以把当前单券主档导出为与标准模板一致的 UTF-8 CSV；完整历史和组合需通过研究库备份保留。

同一债券包含多个观察日期时会形成历史时间线。批量导入较旧历史不会覆盖本机已有的更新快照。

信用页默认先展示三级观察结果；低频的批量导入和单券编辑收在“数据维护”区域，风险信号位于观察结果之后。发行人和组合不对异质债券做简单平均，只展示通过门槛单券的范围与样本数。

## 日历和规则信号

R2 汇总以下本地日程：

- 债券到期日；
- 回售日；
- 评级资料满一年后的人工复核提示；
- 用户设置的下次研究复盘日。

利差相邻可信观察变化达到规则阈值，或日程进入提示窗口时，会生成规则信号。每条信号都保留债券、主体、观察日期、来源和质量状态，并明确要求用户手工确认。

“已确认”只表示用户看过该提示，不表示已经形成投资结论。

## 数据迁移与回退

首次运行 v0.11.0 时，应用会：

1. 保留原有 `credit_observations` 数据；
2. 为原有观察生成首条历史快照；
3. 增加信用历史、组合成员和信号确认表；
4. 将 SQLite `user_version` 从 900 升级到 1100。

升级前已生成并验证 `data/backups/before-v0.11.0-20260718.db`。如果需要整体回退到 v0.10.0，应先停止服务，再恢复该升级前备份；不要用旧版程序继续写入已经升级到 schema 1100 的正式库。

研究项目页的应用内恢复会先创建当前库的 `before-restore-*.db` 安全副本。恢复 schema 900 备份后再次启动 v0.11.0，会重新执行幂等迁移。

## 验收范围

- 后端单元与接口回归 114 项；
- 前端工具、组件与交互回归 52 项；
- CSV、GB18030、Excel、字段映射、多期历史和旧历史不覆盖新快照回归；
- ESLint、Ruff、TypeScript、生产构建和依赖审计；
- 真实 SQLite schema 900 → 1100 副本迁移、完整性和数据量校验；
- 1440×900 与窄窗口浏览器主流程验收。

本产品仅用于个人研究和资料整理，不构成投资建议，也不能替代正式评级、授信审批、估值或风险限额系统。
